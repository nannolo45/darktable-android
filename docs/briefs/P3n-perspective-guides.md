# Brief P3n: perspective guides in rotate and perspective (structure and fit)

Branch `p3n-perspective-guides` from `main`. Read CLAUDE.md, the P3a crop/rotate report and code (CropTool, straighten lines, the on-photo tool infrastructure), and the manual page https://docs.darktable.org/usermanual/development/en/module-reference/processing-modules/rotate-perspective/ (rule 8), then upstream `src/iop/ashift.c` at the pinned commit: structure detection (`_do_get_structure`, line segment detection, contrast/edge enhancement), the line classification and outlier removal, `_do_fit` and its fit modes, the rectangle ("quad") and drawn-lines structure, auto-crop.

The owner chose option A on 25 Nov 2026 (mockups https://claude.ai/artifact/2YXDLCFjRYuURNNn4F9gAh, read the boards' notes for the intent): everything desktop has.

## Deliverables
1. **Engine/bridge:** whatever the bridge needs to run upstream's own structure and fit code on the image the engine already has (never reimplement the maths in the app if upstream functions can be called; if they are static in ashift.c, use the module through its normal entry points as desktop's GUI does, or stop and describe the problem before patching — CLAUDE.md rule 1): get structure (plain, with contrast enhancement, with edge enhancement), the line list with each line's class (vertical used, vertical outlier, horizontal used, horizontal outlier, other), select/deselect lines, the rectangle structure, drawn lines, and fit (vertical / horizontal / both, each also "rotation only" and "lens shift only"). Results written to the module's params exactly as desktop would write them (XMP round trip checked by darktable-cli).
2. **Panel** (all three skins, controls inside the module): structure buttons **rectangle**, **find lines** (with the two enhancement variants, e.g. in a long-press menu or a small option row), **draw lines**; fit buttons **vertical**, **horizontal**, **both**, with the "rotation only" / "lens shift only" variants reachable by long-press; auto-crop (off / largest area / original format) and "show guides" as desktop; the existing sliders stay.
3. **On the photo:** rectangle with four draggable corners; found or drawn lines coloured as desktop (vertical used / outlier, horizontal used / outlier, other — colours from ui-theme tokens matching desktop's meaning); tap a line to select or deselect it, sweep with a finger to change several, a two-finger-free "area" gesture equivalent to desktop's shift+drag (e.g. a selection mode toggle) if it fits; draw a line by dragging in draw mode, delete with long-press. Two fingers always pan/zoom. With auto-crop "original format", the clip region can be dragged as desktop.
4. **Tests:** bridge tests (structure found on a public test image with a building, fit results equal to darktable-cli / desktop logic within tolerance, rectangle fit, drawn lines fit, rotation-only and shift-only); XMP round trip; JVM/controller tests; screenshots in three skins; an emulator scenario (rectangle + fit both changes the render as darktable-cli does).
