# Brief P4b: speed (PLAN.md 6, Phase 4: OpenCL opt-in, cache and tiling tuning)

Branch `p4b-speed` from `main`. Read CLAUDE.md, PLAN.md F1, F8, 2.x build options ("OpenCL off at first"), 3.x render (preview pipeline, cancellable renders), the risk rows on CPU speed and OpenCL, the reports of S1, S2/G0 (benchmark), P2b, P2i (fit view) and P4a (memory numbers, trims). Target phone: Snapdragon 865 / Adreno 650, 12 GB RAM, Android 13 (ColorOS). The emulator has no Adreno: **no phone numbers can be made here**; everything that needs the phone must be made measurable by the owner in one tap.

## Deliverables
1. **OpenCL, opt-in.** Build the engine with darktable's OpenCL support (upstream loads the OpenCL library at run time; nothing to link). In the app manifest declare `<uses-native-library android:name="libOpenCL.so" android:required="false"/>` (and the Qualcomm alias if needed) so the vendor library can be opened on Android 12+. Setting "use the GPU (OpenCL)" in Settings › Processing, **off by default**; when switched on, the app checks that a device was found and runs a short **comparison against the CPU** on a test render (risk row: vendor driver gives wrong results): only if the pictures agree (PSNR threshold stated) does it stay on; otherwise it switches back with a message saying why. Any OpenCL error at render time falls back to the CPU for that render and is logged (P4a crash log). darktable's own OpenCL settings (scheduling profile, per-device options) as desktop's defaults, from darktablerc, with nothing hand-tuned that cannot be measured here.
2. **Benchmark the owner can run.** Settings › Processing › "measure speed": renders a fixed public test RAW (from the test set already in the repo) with the default edit and with a heavier stack (e.g. diffuse or sharpen, local contrast, color calibration, filmic/sigmoid), fit view and 100 % region, CPU and (if on) GPU, three runs each; shows the times and copies them as text, so the owner can paste them. No upload.
3. **Cache and tiling tuning**, from the P4a numbers and darktable's resource model: choose darktable's resource level / `resource_*` values for a 12 GB phone (and a safe default for smaller phones by total RAM), the pipeline cache size, and the image cache size, so that switching photos in a series is fast without being killed by Android. Make each choice a named constant with the reason; expose only "processing memory: normal / more / less" to the user if it helps. Measure on the emulator what can be measured (memory, cache hits), labelled x86_64.
4. **Lighter work during a gesture**, only where measurement shows a gain: e.g. skip redundant preview renders while a slider is dragged (coalesce), keep the full-quality render for when the finger lifts. No change to results.
5. **Tests:** OpenCL disabled path unchanged (all existing tests green); the comparison logic with a fake engine (agreeing / disagreeing / device missing / error mid-render); benchmark screen and copy; resource choice by RAM size; coalescing does not drop the last value. CI as usual.
